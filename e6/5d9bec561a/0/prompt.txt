# Plan: Add zstd Compression to JSONL Transcript Storage

## Context

JSONL transcript files account for 97.7% of git object size (4.3 GB / 1,062 files). On-disk, the repo goes from 4 MB to 419 MB with checkpoints. The biggest pain: `git push` of `entire/checkpoints/v1` takes 10-20s because git must transfer large uncompressed blobs. JSONL is highly redundant (~90% structural repetition), achieving 10-15x compression with zstd.

**Goal:** Compress JSONL transcripts with zstd before storing as git blobs, reducing object sizes 10-15x. Add a migration command so existing users see immediate improvement.

## Approach

- Compress after redaction, before blob creation; decompress after blob read, before consumption
- Content hash remains on pre-compression (redacted) data for dedup consistency
- Compressed files use `.zst` suffix (e.g., `full.jsonl.zst`)
- Read paths check for `.zst` first, fall back to uncompressed (backward compat)
- `github.com/klauspost/compress` v1.17.11 is already an indirect dependency (promote to direct)
- **Migration command** (`entire optimize`) rewrites the metadata branch tree to compress existing data
- **Benchmarks** prove the improvement with simulated realistic workloads

## Key Design Decisions

1. **Compress before chunking** — zstd reduces 24 MB → ~2 MB, so most transcripts fit in one blob. Compressed chunks use raw byte splitting (no JSONL line-boundary awareness needed).

2. **Migration for existing data** — `entire optimize` rewrites the `entire/checkpoints/v1` HEAD tree, replacing all `full.jsonl*` blobs with compressed `full.jsonl.zst*` blobs. Uses `ApplyTreeChanges()` tree surgery for O(depth) performance.

3. **Shadow branch transcripts also compressed** — `.entire/metadata/<session>/full.jsonl` files from disk are redacted, compressed, stored as `full.jsonl.zst` blobs.

## Part B: Migration Command (`entire optimize`)

### Step 13: Add `entire optimize` command

**New file:** `cmd/entire/cli/commands/optimize.go`

```
entire optimize [--dry-run]
```

**Implementation using `ApplyTreeChanges` tree surgery** (NOT the old FlattenTree pattern):

1. Get `entire/checkpoints/v1` branch ref and HEAD commit/tree
2. Walk the tree recursively to identify uncompressed transcript blobs:
   - `*/full.jsonl` (and `*.001`, `.002` chunks)
   - `*/agent-*.jsonl`
3. Build `[]TreeChange` slice: for each uncompressed blob, read → compress → create new compressed blob → add change (delete old path, insert new `.zst` path)
4. `ApplyTreeChanges()` → create commit → update branch ref
5. Report: N files compressed, before/after total size

**Dry-run mode** (default): scan and report what would be compressed + estimated savings, without modifying anything.

**Key reusable functions:**
- `checkpoint.ApplyTreeChanges()` (parse_tree.go:197) — O(depth) tree surgery
- `checkpoint.CreateBlobFromContent()` (committed.go) — blob creation
- `compression.Compress()` / `compression.IsCompressedName()` — from Step 1
